Order flow

Every order placed through the load balancer, followed through Postgres, the queue and the notifier. Statuses come from the Lambda's logs and the dead-letter queue, because the orders table never learns whether the customer was told.

Orders go through localhost:8000 like any customer's. A poison order is accepted like any other; only the notifier rejects it.

    Reading the emulatorOrders, queues and logs load in a couple of seconds.

    Read every 2 seconds from the orders table (through the API), both CloudWatch log groups by trace id, the queue and DLQ attributes, and the event source mapping. Delayed is the queue's 60-second visibility timeout: a failed message stays invisible that long before the next attempt. Locally dlq-not-empty stays OK because the emulator does not publish AWS/SQS metrics; notification-failures is the alarm that fires. Click an order to open its trace; the address bar then links straight to it.
